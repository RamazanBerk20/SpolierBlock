# Pitfalls

Traps specific to this repository, each checked against the code or the commit history at version 0.2.6. Read the section for the area you are about to change.

## Models

- **SigLIP 2 breaks under ordinary int8 quantisation.** Dynamic or static int8 of the activations gives a cosine of about 0.7 against fp32. Weight-only int8 gives 0.9998. So `tools/quantize-vision.mjs` quantises only the MatMul weights (int8 plus a scale per output column, restored by a `DequantizeLinear` node) and the activations stay fp32. Do not replace it with `onnxruntime.quantization` or with a ready-made `*_quantized.onnx` file. (`quantize-vision.mjs` header, commit 58060f2.)
- **Weight-only int8 costs time on every run.** The weights are restored on each inference, which is why title checks run in batches of up to 4. Since 0.2.1 the engine folds them to fp32 at load (`disable_quant_qdq`): faster, same scores, but the process is about 1 GB, at the owner's memory budget. Do not add another large model to that process without removing this. (`engine.js`.) Android folds the weights only inside the optional NNAPI session, on devices with at least 6 GB, after a self-check (`Accel.java`).
- **The int8 MiniLM classifier is scored one sentence at a time.** It quantises activations per tensor, so padding or batching sentences changes the scores. Do not batch in `classify`. The post's score is the maximum over sentences, so one spoiler sentence is not diluted. (`engine.js`.)
- **Held-out files are never used for training, tuning or choosing a threshold.** That is `test/fixtures/spoiler-eval.jsonl`, `spoiler-eval2.jsonl` and the held-out half of the image calibration. `finetune.py` chooses the threshold on validation items only. If you retrain, read both eval files once, at the end, and report what you found with its caveat. (`train-spoiler.mjs` header.)
- **`fp-posts.jsonl` is a tuning benchmark, not a held-out one.** The matcher rules were adjusted while looking at it. Do not quote a further improvement on it as evidence.
- **The shipped image cut-offs are fitted on all calibration images**, including `test/fixtures/images`. Only the two-fold line of `tools/calibrate-clip.mjs` is held out. The held-out line needs the research image sets (`SB_RESEARCH=research`), which are not in git.
- **Thumbnail text is all capitals and full of logos, so single words from OCR never match.** Text read from pictures goes to the matcher behind one U+0001 and counts only for names the index marks `ocr` (two or more words as written, not a single word, not a sequel-number swap). Do not loosen that to catch "MINECRAFT" on a thumbnail: `tools/fp-ocr.mjs` shows what a single word costs. Strip U+0001 from page and app text, as both platforms do, or a page can pose as OCR text. (`matcher.js`, `build-index.js`, `domText` in `content.js`, `Scanner.java`.)
- **Headline Case titles carry no case evidence.** A video title in Title Case or capitals ("Why Arcane Is The Best Show Of The Decade") would make every capitalised everyday word look like a title. In an ALL-CAPS run or a Headline Case line a name that relies on case needs a media word next to it; a distinctive single word (not an everyday word in any shipped list, work with at least 45 sitelinks) still matches. The rules were chosen with `test/fixtures/headlines.jsonl`, which is therefore tuned-on. (`caseless` in `matcher.js`, `DISTINCT_POP` in `build-index.js`.)
- **The common-word list decides a lot.** A word missing from `tools/catalog/common-words.txt` counts as distinctive ("Scrubs", "Vertigo" match as plain words). Rebuild it with `tools/catalog/words.mjs` and rebuild the catalog and the index together; the index rules use fixed line ranges of the file (first 1,000, 3,000 and 10,000 lines), so keep the English 20k list first.
- **PP-OCR boxes are axis-aligned.** Slanted text (more than about 10 degrees) reads worse. It is a known `shortcut` in `ocr.js`, not a bug to fix in passing.

## Browser runtime

- **Firefox has one WASM thread and a lazy event page.** Extension pages in Firefox cannot be cross-origin isolated, so there is no `SharedArrayBuffer` and the models run on one thread (per image in a screenful, a title check took 426 ms against Chrome's 171 ms with four threads, in the 0.2.1 figures). The event page may not be running when a content script sends a request, so `ask()` in `content.js` retries a few times on "Receiving end does not exist" instead of failing open. Do not make a request failure reveal a picture without that retry. (Commit 431ace9.)
- **A Chrome service worker cannot host the WASM runtime.** The engine runs in an offscreen document. `offscreen.js` registers its message listener before it loads the engine, because a message sent right after the document is created must find a receiver. `background.js` shares one promise for creating the document, because two early messages used to race. Keep `target: 'offscreen'` on forwarded messages.
- **`img.currentSrc` updates late in Firefox.** It changes only once the new picture starts loading, so a recycled `<img>` with a new `src` looked unchanged and kept its old verdict. The content script decides on the attribute change (`src`, `srcset`, `poster`, with the mutation's old value). Do not go back to comparing `currentSrc` alone. (Commit 431ace9.)
- **Every frame loads its own index.** The content script runs in all frames, so a page with several iframes pays the index size (about 3.5 MB: `index.bin` 1.57 MB plus `index.json` 1.96 MB in `dist/firefox/data`) per frame. Counts and the toolbar badge come from the top frame only.
- **The binary index doubles when the key count passes its load limit.** `buildIndexBinary` (`src/content/matcher.js`) sizes the hash table to the smallest power of two of at least 1.6 times the key count, 12 bytes a slot. The current build has 77,633 keys (`node` call of `buildIndex` on `data/catalog.json`; `npm run build` prints it as "index: N keys") in 2^17 = 131,072 slots, so the limit is 81,920 keys (131,072 / 1.6) and there is room for 4,287 more. One key more than that and the table has 2^18 slots: `index.bin` goes from 1.57 MB to about 3.1 MB, in every frame. The opt-in catalog update on the device builds the index with the same code, so a few thousand new works can cross the limit there. Watch the key count after catalog changes.
- **Closed shadow roots need an API.** `openOrClosedShadowRoot` is `element.openOrClosedShadowRoot` in Firefox and `chrome.dom.openOrClosedShadowRoot` in Chrome; both are used in `shadowOf`. A custom element that is not yet defined gets its root on upgrade, which no mutation reports, so it is retried for 30 seconds.

## Covers and layout

- **A cover must not change the measured size of anything.** Virtualised feeds (X, Reddit, YouTube) position posts by measured height. The cover is absolutely positioned with `!important` rules and size containment, content is hidden with `visibility` (never `display`), pending media is dimmed with `filter`, and `position: relative` is set only on a static block. The forced minimum height of 0.1 is gone: do not bring it back. The e2e recycled-feed case checks heights.
- **`all: initial` on the cover's `:host` resets `visibility`.** That is why the host sets `visibility: inherit !important`: without it a cover inside a container the page hides would show anyway, and a nested cover under an outer one too. (Commit 50c5d66.)
- **`<meta name="color-scheme">` leaves the computed `color-scheme` at `normal`.** A page that declares its scheme only in the meta tag looked light to the cover's colour fallback. `isDark` in `content.js` reads the meta tag when the property says `normal`, and treats a page that allows only one scheme as that scheme whatever the system says. The e2e dark-page case checks it.
- **A cover is recomputed from what the block shows now.** Verdicts live per picture and per source URL, not per block. A recycled node must not keep the cover of its previous post. If you cache a decision on a block, key it by the text and the pictures it shows.
- **Do not decide from a wrapper.** A late verdict covers the post found by `findMediaBlock`, not the picture's immediate parent.

## Build and data

- **`npm run build:fixture` overwrites `dist/` and `build/data/`.** The e2e runner needs the fixture build; afterwards `dist/` holds the small test catalog until you run `npm run build` again. Do not hand `dist/` to anyone after an e2e session without rebuilding.
- **Catalog query strings are cache keys.** `tools/catalog/build.mjs` caches every Wikidata answer by the sha1 of the query text in `tools/catalog/cache/`. Changing a string in `src/shared/catalog-rules.js` (even a space) re-runs those queries, which are slow and polite. The name lookup uses 400 fixed buckets for the same reason. `tools/build.mjs` reads the same cache for the class lists and asks Wikidata when it is missing, so a worktree without the cache link needs the network.
- **`builtAt` is the catalog file's modification time.** `tools/build.mjs` writes it into `catalog-info.json`. The stored `catalogIndex` is valid only for the `builtAt` it was built against, and the catalog update's window starts at January 1 of the year before `builtAt`. A fresh checkout gives `data/catalog.json` a new modification time, so a build from a later checkout has a later `builtAt`. If you build releases from checkouts, set the file's time to the real catalog date first.
- **The index files go together.** `index.bin` (hashes) and `index.json` (groups, titles) are one artefact, built by the same call. The title rows in `clip-meta.json` refer to groups of the bundled `index.json`; a rebuilt index maps them back through `meta.fromBundled`. Do not mix files from two builds.
- **The Chrome manifest is derived.** Edit `manifest.json` (the Firefox form). The build deletes `browser_specific_settings` and rewrites `background` for Chrome, and pushes `offscreen` into `permissions`. Do not put Chrome-only keys in the source manifest.
- **The first build downloads about 1 GB** (vision model, text model, tokenizer, OCR files). Files are pinned by revision and sha256; if a download fails the check, do not loosen the check.
- **`research/` is mostly not in git.** `SB_RESEARCH=research` and some tools need files that exist only in the owner's checkout.
- **`package.json` still lists `tesseract.js` and `@tesseract.js-data/eng`.** Nothing in the build, the extension, the tests or the Android build uses them now; only `research/scripts/v2-ocr-eval.mjs` and `ocr-tesseract.mjs` do.

## Android

- **Image capture must not draw host render nodes.** The capture draws only the `ImageView`'s drawable (`Images.drawContent`). `View.draw` on a hardware canvas puts the host's own `RenderNode`s (background, overlay children) into the capture renderer, and whichever renderer syncs a shared node first takes its damage. On devices with partial screen updates the app's next frame then leaves those regions unpainted: stale covers and posts, a feed that "jumps". The fix was checked by frame counters in the demo on the emulator. The owner has not reported the jump again after running 0.2.0 on a phone, but no counter or log from that run exists here.
- **Public Android APIs only, no resources, no AndroidX** in `extensions/blocker`. The library is merged into other apps' APKs. ONNX Runtime's Java classes are the only dependency that reaches the dex; the patch ships its native libraries separately.
- **The provider's caller check is a package name.** `Store.CALLERS` is the allow-list; see [android.md](../android.md#the-companion-app-and-the-shared-config) for what that does not protect. Add a package to the list only for an app the patch supports.
- **A frozen app gets change notices late.** The shared config is refetched on every activity resume for that reason.
- **Obfuscated hosts.** Never fingerprint on obfuscated names. The patch finds the Application class from the manifest and hooks framework methods (`NotificationManager.notify`) and view classes named in layout XML (`TextContentView`, `IgTextLayoutView`). A hook that is not found only logs a warning.
- **A host app can wrap `Window.Callback` after us.** Instagram's Reels viewer installs a gesture handler around the window callback that keeps plain taps to itself. If the blocker's `TouchGate` is not outermost, a tap on a cover's buttons never reaches it. `Scanner.gate()` puts the gate back on top every frame; `TouchGate` has a depth counter so a gate further in does not handle an event twice. Do not install the gate once and forget it. This is from reading Instagram 452.1 and from the demo's wrapper (`Reels.tapWrapper`); it never ran in Instagram.
- **App views float over covered items.** X's bottom bar and compose button lie over the list, so a covered post's visible rectangle (clipped only by its ancestors) extends under them. `Scanner.coverAt` gives the touch to the app when `appOnTop` finds something clickable drawn above the item there; "above" follows the framework's order (higher Z first, then later index), so a later sibling with a lower Z is under the item and must not count, or a tap would pass through a cover to the post. Reproduced and checked in the demo (`--ez bottomBar true`, `android/tools/demo-bar.sh`) on the emulator only.
- **Cards outside lists catch app chrome.** The first version of `Scanner.looseItem` took any clickable view outside the lists and covered YouTube's search bar, whose query ("dune part two trailer") is a clickable `TextView`. A loose card is never a `TextView` and needs at least 3 words; YouTube's end card is a plain clickable `View` with a content description, so do not narrow the rule to `ViewGroup`s. Look at `block ... loose` lines in the debug log after changing it (emulator, YouTube 21.30).
- **Muting must not follow every cover.** A covered post with a video next to an uncovered one muted the uncovered one (owner's report, X and YouTube). `Scanner.hidesSound` now leaves the sound on while an uncovered video surface is at least half on screen; a surface under a cover's visible part (a pager's shared player) counts as covered. The demo's watch and reels screens (`demo-watch.sh`) check both directions.
- **A full-screen pager's single page must be covered as one item.** A `RecyclerView` or pager showing one page at rest (Reels, Shorts) has one child. Unwrapping single-child chains for every container made that page's own children the items instead of the page. `Scanner.itemParent` looks into single children only for a container whose class name ends in `ScrollView`.
- **The X quote hook reads an obfuscated field.** `QuoteView`'s text is a field named `O` in X 12.19.1. The patch skips the hook with a warning if the class, method, field or two free registers are missing. Check the log after patching another X version.
- **The Android image code follows the browser's, file for file.** `Images.visionPixels` ports `pixels.js`, `Clip.java` ports the verdict in `engine.js`, `Ocr.java` ports `ocr.js`. The cut-offs are read from `clip-meta.json`, not written into Java. Change the JavaScript first, regenerate the vectors (`android/tools/clip-vectors.mjs`) and make `ClipTest` and `OcrTest` pass. The bundle reads `models/vision/model.onnx`, `data/clip-text.bin`, `data/clip-meta.json` and `models/ocr/*` from `dist/firefox`.
- **ONNX Runtime stays at 1.22 on Android, and `OcrTest` runs on 1.32.** Desktop (Linux x86-64) ORT 1.22 to 1.31 give the PP-OCR v5 detector a blank probability map, so `OcrTest` has its own Gradle task (`ocrTestDebugUnitTest`) on desktop 1.32. The Android 1.22 build reads the fixtures correctly. Do not move the app to 1.32 without a reason (the bundle was 154 MB on 1.32 and 138 MB on 1.22), and do not fold the OCR test back into `testDebugUnitTest`.
- **XNNPACK is not used.** It was slower than the plain CPU session on the emulator and crashed on 1.22. Hardware acceleration is NNAPI only, behind the self-check and the crash marker in `Accel.java`. Never remove the marker logic: a native crash cannot be caught, and without the marker a crashing device would crash on every start.
- **The emulator is x86_64.** arm64 builds run under translation (Android 11 and newer images). Timings from it say little about a phone.
- **Only one emulator and one Gradle job at a time**, under the heavy lock.
- **A background emulator keeps the heavy lock.** `flock ~/.cache/sb-heavy.lock script.sh` hands the lock's file descriptor to every child, so an emulator started in the background from that script holds the lock until it exits, and the next `flock` waits forever (a 9-hour deadlock on 2026-11-21). Start the emulator outside the lock, or with the descriptor closed: `flock 9 ...` with `emulator ... 9>&- &`, or from a separate `setsid` shell that did not inherit it. Shut it down before taking the lock again.

## State keys and visibility (0.2.3)

- **A "Show once" key (or any state key) must not contain volatile text.** The 0.2.2 key on Android included the text of ticking counters (like counts), so a shown post was covered again each time a count moved. The key is now the post's own text with numbers blanked (`Scanner.shownKey`), and the same in the extension since 0.2.5 (`showKey` in `content.js`: runs of digits become `#`, whitespace collapsed); a post with no words is keyed by its pictures, minus video players, whose key changes with every sampled frame. The price: two posts with identical text share the choice. The demo's ticking counters and `--ei watchShown` check it.
- **A cover's rectangle must be clipped to what is visible before it is used for shading, muting or touch.** An item scrolled partly under a pinned view still has its full bounds. Using them shaded and muted YouTube's pinned watch-page player and let covers take taps outside their list. `Scanner.visibleOnScreen` (`getGlobalVisibleRect`, which clips to every ancestor) is used by `shadeFloaters` and `coverAt`. There is still no "moves with the item" check. The demo's `watch` screen counts shades and taps on the pinned player.
- **The benchmarks had no plain sentences about famous multi-word titles.** `fp-posts.jsonl`, `headlines.jsonl` and `ocr-noise.jsonl` never said "Resident Evil is scary", so the flag that made such names need a media word cost recall nobody saw (the test allows at most 46 of 1,200 sentences to miss, 367 missed before the fix). `test/fixtures/top-names.json` and the plain-sentence test in `test/catalog.test.js` are the guard. Run `npm test` after any change to the `common`, `ambiguous` or `fame` rules, and read the benchmarks as tuned-on.
- **Host apps put metadata in content descriptions.** A YouTube row's description is "title - duration - Go to channel C - C - views - age - play video" (localised), so "45 minutes" reached the matcher and matched a numeric title. `YouTubeText.strip` cuts it from the row's structure, not from phrase lists (a language that writes the number after the unit word would defeat it). Small tappable icons' descriptions are skipped in every app. Look at the verbose log (`adb shell setprop log.tag.SpoilerBlock VERBOSE`) before assuming a name was in the post.
- **A bare name is its closest works, not every work that carries it.** A missing franchise entry is fixed where the group is built: `closest` in `build-index.js`, ported in `Catalog.java` (the on-device catalog update rebuilds the index with it). Change both and run the vectors. `test/fixtures/franchises.json` is reviewed by hand; change it only after looking at the new group.

## Stale comments you will meet

These comments in the code no longer match it. Do not trust them, and fix them when you are in the file anyway:

- `content.js`: "the engine itself gives up on a recognition after 10 s". The engine has no OCR time limit now; the 60 second safety net in the content script is what remains.
- `Scanner.java` (`activityWindow`): "no TouchGate: covers there have no buttons". Dialogs and popups do get buttons, through a transparent view on top of the window.
- `base.css`: "the near-black of the in-page cover". The real cover is a light or dark grey panel.
- `research/REPORT.md` describes 0.1-era models and figures.

## Symlinks to ignored folders get committed, and merging them deletes the real folder

An ignore rule with a trailing slash (`keystore/`) matches a directory, not a symlink of the same name. An agent that
symlinks `android/keystore` or `android/apks` into its worktree and then runs `git add -A` commits the symlink. Merging
that branch into a checkout where the name is a real, ignored directory makes git delete the directory's contents to put
the symlink there. This destroyed the local signing key and the supplied APKs once (2026-11-18). The ignore rules now
have no trailing slash. Before merging an agent branch, run `git ls-tree -r <branch> | grep ^120000` and refuse symlinks.
Copy small local files into a worktree instead of symlinking them, and stage files by name.
